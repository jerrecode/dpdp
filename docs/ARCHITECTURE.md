# Native pairing, endpoint discovery and application transport

## Trust and storage

The stable 128-bit legacy node ID identifies a record; a locally pinned Ed25519
SubjectPublicKeyInfo public key authenticates that association. Reported names are
mutable labels and may collide. Native signing keys are generated by GnuTLS and
stored as mode-0600 **PKCS#8 PEM** (`<config>.signing.pem`). PKCS#8 matters:
GnuTLS's older generic export emits an UNKNOWN envelope for Ed25519, which cannot
be reloaded. A regression test reloads the persisted key and compares public keys.

`<config>.paired.json` is separate from the user-editable status registry. Pins,
SSH material, pending enrollments, revocation epoch and last verified endpoint
are read/updated under a sidecar lock with complete strict JSON parsing, same-directory
atomic rename and fsync. Unknown status-registry metadata is preserved by full ID;
its display keys are never an authorization boundary. Private key reads reject
symlinks, non-regular files, foreign ownership and permissive file modes.

## Pairing

1. A foreground Debian listener generates a uniform six-digit code, including
   leading zeroes. Bind TCP on the selected IPv4 address and UDP discovery port+1.
   One local pairing listener per config; 120 seconds, three accepted attempts.
2. BoringSSL SPAKE2 exchanges two fixed 32-byte messages. Different client/server
   roles and `DPDP-PAIR-2 client/server` names bind protocol context. Upstream commit
   `e651545da6e26e1f4420723a3b69a78ed1b9c51d` is statically built; DPDP contains no
   PAKE arithmetic. The full 64-byte result becomes an external GnuTLS TLS PSK.
3. Negotiate TLS **1.3 only**, with tickets disabled. Wrong code yields different
   keys and fails TLS key confirmation. The six-digit code is never a raw TLS PSK.
4. Exchange bounded JSON envelopes containing an identity payload and Ed25519 proof
   over `DPDP-PAIR-2|ROLE|TLS_EXPORTER_HEX|PAYLOAD`. Roles differ; the client checks
   the discovered target ID. Each side proves possession of its signing key and
   binds the SSH keys to this authenticated channel.
5. Persist a pending record with a random transaction token and enrollment epoch;
   exchange commit acknowledgements; serialize SSH authorization and final commit
   under the pairing-store lock. Revocation rotates a global epoch, cancelling
   enrollments begun before it. Neither a stale token nor a delayed handshake can
   silently clear a successful revocation. Matching-key retries recover partial
   enrollment; different keys cannot overwrite an existing pin.

Handshake, PAKE and application records share one absolute ten-second deadline,
clamped to the remaining listener window. Record sizes are capped at 8192 bytes.
Secret material is not passed through argv/environment. The temporary code is
shown only by the foreground pairing command. `pair-watch` is an interactive
assistant reading the daemon's discovered-peer registry; it is not a hidden prompt
inside a systemd/Termux boot service.

GnuTLS TLS-SRP was investigated, then rejected after actual package testing:
current GnuTLS defaults disable it and Termux OpenSSL explicitly uses no-srp.
SPAKE2 + TLS1.3 avoids restoring legacy TLS/CBC suites. BoringSSL's API is pinned,
not assumed ABI-stable; upgrades require rebuilding and rerunning tests. The
upstream SPAKE2 implementation is used as provided, not claimed wire-compatible
with every RFC9382 implementation. Dependency updates remain a maintenance task.

## Signed IPv4 discovery

Group `239.255.77.81`, default UDP port `47981`, TTL=1. V2 payload:

```
DPDP/2|KIND|NODE_ID|NAME|SOURCE_IPV4|NONCE|ECHO|SIGNATURE
```

`KIND` is Q (challenge), A (answer), U (address-change hint). Node ID is 32 lower-case
hex characters; name is 1–48 ASCII label characters; NONCE/ECHO are 16-byte random
values encoded as 32 hex characters (ECHO may be `-` outside answers). SIGNATURE is
64-byte Ed25519 encoded as 128 hex characters over the exact preceding payload,
excluding its separator and signature field. Maximum receive buffer is 512 bytes;
frames of 512 or more bytes, embedded NULs, extra/invalid fields and unknown pins
are rejected.

Each daemon issues a new challenge every min(announce_seconds,15) seconds. A paired
answer must echo the current local nonce within 45 seconds, match its signed IP
to UDP source metadata, verify under the pinned key, and not already have been
accepted for this peer/challenge. Only then update authenticated endpoint state,
start authorized hooks, and connect SSH. No synchronized wall clock is required
for packet freshness. The recent CLI endpoint cache additionally expires after
90 seconds and fails closed after backward clock jumps.

Q/U signatures do not prove fresh endpoint reachability. They trigger bounded
answers/challenges, never authorize services directly. U is sent from the new
address to remembered peer addresses and multicast as fallback. Periodic multicast
also recovers simultaneous address changes and missed hints. Both multicast and
unicast sends use `sendmsg(IP_PKTINFO)` to select source IP **and** interface;
`IP_MULTICAST_IF` alone would not constrain unicast replies on a dual-NIC PC.
Receive-side IP_PKTINFO filters other interfaces. Control buffers are aligned.

Input processing is capped at 32 packets/second; signed query/hint responses at
one per peer/second. State is capped at 128 peers/pins. Paired peers may evict
unverified memory entries so a legacy-ID flood cannot reserve every slot; persisted
user metadata is not deleted. Discovery remains confined to the selected IPv4 LAN.

V1 `DPDP/1|Q/A|ID|NAME|SEQUENCE` remains experimental candidate discovery, with its
255-byte limit and strict unsigned-64-bit sequence parser. V1 has no authentication
or replay defense. It cannot overwrite a currently authenticated endpoint or trigger
hooks, even when its ID has legacy trusted=true. Both devices must upgrade; old
binaries do not acquire these protections automatically.

## SSH and hooks

Pairing includes a dedicated Ed25519 SSH client public key. Local `access-init`
explicitly offers a locally derived non-root account, Ed25519 sshd host key and
port. Only a completed enrollment with that local offer writes a managed line to
`~/.ssh/authorized_keys`. Existing lines are preserved under cooperative lock and
atomic replacement. Public key blobs are structurally validated; options, comments,
newlines and non-Ed25519 SSH keys are rejected from wire identities.

OpenSSH helpers use direct exec argument arrays, strict host checking against a
private per-peer known_hosts file, identity aliases, only the dedicated private key,
short connection timeouts/keepalives and the selected local source IP. Control
socket names hash the full identity and verified endpoint; owner sidecars retain
full node IDs for exact revocation. Paths leave space for OpenSSH's temporary
socket suffix on Termux. SFTP/scp (OpenSSH9+) provide file browsing/transfers;
explicit SSH TCP forwarding carries other applications. DPDP does not implement
new file/control protocols or transparent TCP migration.

At most eight daemon-managed SSH workers run, including workers still shutting down,
with 30-second retry after failure. Helpers supervise their OpenSSH child, recheck
authorization/endpoint each second while scheduled, and forward shutdown signals.
OpenSSH background persistence is disabled: managed or explicit foreground masters
provide sharing without an untracked detached master. One runtime lock prevents
duplicate daemons for the same configuration.
At most 32 hook children are active. Hooks additionally require local boolean
trusted=true and configured absolute executables; no wire message supplies a
command. Hook supervision/exactly-once semantics remain limited to one-shot
peer/endpoint transitions. Applications must handle reconnection/idempotence.

Unpairing denies fresh DPDP proofs, removes managed authorized_keys lines and
requests closure of local outbound masters. **Already authenticated inbound SSH
connections/channels are external sshd sessions and are not terminated by this
operation.** Immediate server-wide session cutoff is a separate administration
operation. This is intentionally a narrower contract than universal session
revocation; issue #1/#3 remain open for that and key-rotation/supervision work.

## Platforms and remaining validation

One C runtime on Debian and Termux; platform install/startup remains shell. GnuTLS
and json-c are shared libraries; BoringSSL PAKE is statically linked, with C++17
build/link tooling but no bespoke crypto implementation. Python is test-only.
Android SSID fail-closed sleeps and no permanent wake lock remain unchanged.
Physical USB adapter routing/DNS, Android multicast/background execution, battery
usage, full IPv6/netlink integration and external sshd policy need further tests.
